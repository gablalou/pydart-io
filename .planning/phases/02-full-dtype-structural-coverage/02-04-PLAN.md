<objective>
Deliver CONV-06 (datetime + tz timestamp) and CONV-07 (timedelta) as a single vertical slice (they
share the same FFI mechanism and the same ns-only resolution gate): classify -> gate -> convert ->
round-trip.

Behavior delivered:
- datetime64[ns], datetime64[ns, tz], and timedelta64[ns] columns round-trip correctly, mapping to
  Arrow Timestamp(Nanosecond, tz) / Duration(Nanosecond) (D-15).
- tz-aware timestamps round-trip the tz string exactly as-is, no UTC normalization (D-16).
- Non-ns-resolution temporal columns are rejected with a clear, actionable flint.FlintError that
  names the resolution AND explains pandas 3.0's microsecond-default gotcha with an .astype fix
  suggestion (D-15 / RESEARCH Pitfall 5) -- because the most common pandas-3.0 way to build a
  datetime column (pd.to_datetime with no unit) now yields us, which Flint rejects.

Purpose: the conversion mechanics are already generic (RESEARCH Pitfall 0 confirmed
datetime/tz/timedelta round-trip through the existing path); the new work is a dtype-classification
gate plus an actionable rejection message. No new FFI/marshalling code, no hand-rolled tz logic.
Output: ArrowKind::Timestamp{tz} + Duration, three classify_dtype temporal entry points with ns
gating, and a temporal test file covering both round-trips and the pandas-3.0 rejection path.
</objective>
