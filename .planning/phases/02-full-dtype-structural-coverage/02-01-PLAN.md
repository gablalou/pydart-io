<objective>
Deliver CONV-03 (nulls) end-to-end as the phase's first vertical slice, and in doing so establish
the isinstance-first `classify_dtype` dispatch that every later dtype family extends.

Behavior delivered (behavior-first, per MVP mode):
- A nullable ArrowDtype numeric column (with real pd.NA nulls) is confirmed to round-trip with null
  positions preserved (D-07). This already works mechanically via Phase 1's `__arrow_c_stream__`
  import; this slice proves it with tests and guards the classification path around it.
- Masked pandas extension dtypes (Int64 / boolean / Float64) now get an honest `flint.FlintError`
  naming the column and dtype instead of the raw `AttributeError: 'IntegerArray' object has no
  attribute 'flags'` crash they hit today (D-08 / RESEARCH Pitfall 1).
- Plain numpy NaN columns are deliberately left on the unchanged zero-copy numeric path (D-09).

The enabler is restructuring `classify_dtype` from `dtype.kind`-first to `isinstance`-first
dispatch (RESEARCH's centerpiece fix). This is NOT a standalone refactor: it is the minimal
mechanism required to make the masked-extension rejection honest, which is the concrete CONV-03
deliverable above.

Also lands the early Assumption A1 probe: a direct Rust unit test that `arrow::compute::concat`
handles DictionaryArray / TimestampArray(tz) / DurationArray, so Plans 03-04 can rely on the
existing multi-chunk fallback without type-specific handling.

Purpose: unblock all subsequent dtype-family slices with a correct classification skeleton and a
de-risked concat assumption.
Output: restructured `classify_dtype`, a Rust concat probe test, and a Python nulls/rejection test.
</objective>
