<objective>
Generalize the skeleton's thin numeric conversion into the full Phase 1 pandas-boundary decision matrix and build the diagnostics/strict-mode surface on top of it. Introduce a single per-column decision function `plan_column` (in pure-Rust `flint-core`) that both `from_pandas`/`to_pandas` AND the strict-mode/`copy_report()` surface consume — one source of truth so DIAG-01 and DIAG-02 can never silently disagree (RESEARCH.md Pitfall 2).

Purpose: Deliver the genuinely new, hand-written work of this phase — the pandas copy-vs-borrow logic and the honest diagnostics contract (D-03, D-04) that this project exists to do better than pyarrow. Bake in the locked bool resolution: `ArrowDtype`-backed bool is zero-copy and strict mode SUCCEEDS on it (Success Criterion 2); numpy-backed bool is a strict-mode-REJECTED, clearly-named copy-required case (never a silent copy).

Output: A per-column decision function; a generalized `from_pandas`/`to_pandas`; `from_pandas(df, strict=True)` raising `flint.ZeroCopyRequiredError`; `table.copy_report()` returning `list[ColumnCopyStatus]`; and tests proving the success/rejection matrix.

Covers CONV-01, CONV-02 (full numeric+bool decision matrix), DIAG-01 (strict mode, D-03), DIAG-02 (copy_report, D-04). The zero-copy PROOF (D-06) is Plan 03; PyCapsule interop (CAP-01/CAP-02) is Plan 04.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pandas/numpy buffer memory → Rust core | `from_pandas` borrows numpy/Arrow buffers; a crafted stride/offset could be misread |
| Rust `Drop` ↔ Python refcount | Releasing a borrowed buffer's owner touches Python refcounts, possibly off the main thread |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03 | Tampering | `from_pandas` numpy buffer borrow (`crates/flint-python/src/pandas.rs`) | high | mitigate | Explicitly check contiguity and zero offset before treating a numpy buffer as directly borrowable; a non-contiguous/offset buffer is routed to `RequiresCopy` (via `plan_column`), never borrowed as contiguous — prevents an out-of-bounds read (RESEARCH.md Security Domain). Borrow only through the `rust-numpy` crate, never raw pointer capture. |
| T-01-04 | Tampering (memory corruption) / DoS | Rust `Drop` on a borrowed pandas/numpy buffer owner | high | mitigate | Any refcount decrement on a borrowed Python buffer's owner reacquires the GIL via `Python::with_gil` before touching Python state (RESEARCH.md line 435 / ARCHITECTURE.md Flow 2 ownership hazard). |
| T-01-05 | Repudiation | strict mode vs copy_report disagreeing (credibility of the zero-copy contract) | medium | mitigate | Both features consume the single `plan_column` function; a test asserts per-column agreement, so the "strict says X, report says Y" credibility failure cannot occur silently (RESEARCH.md Pitfall 2). |
</threat_model>
