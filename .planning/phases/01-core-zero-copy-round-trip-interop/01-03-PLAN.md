<objective>
Prove the project's reason to exist: that the numeric/`ArrowDtype` conversion path is genuinely zero-copy, using BOTH independent proofs required by D-06 — a Python-side pointer-identity check (same physical memory address before/after conversion) AND a Rust-side allocation-counting check (no new heap allocation for the data buffer). Neither alone is sufficient (RESEARCH.md Summary line 51); both must pass.

Purpose: The zero-copy claim is the core value of the project (STATE.md: "must work and must be provably faster, or the project has no reason to exist"). This plan is the verification harness that makes CONV-01/CONV-02's "true zero-copy (no data duplication)" a measured fact rather than an assertion, and guards against the well-documented allocation-counter false-negative from optimizer elision (RESEARCH.md Pitfall 4).

Output: `tests/python/test_zero_copy_pointer.py` (forward and reverse pointer identity) and `tests/rust/zero_copy_alloc.rs` (allocation count == 0 with a `std::hint::black_box` guard and a sanity check).

Covers CONV-01, CONV-02 (the zero-copy proof, per D-06). This plan touches only test files — the conversion code and `buffer_address` accessor it exercises come from Plans 01/02.
</objective>
