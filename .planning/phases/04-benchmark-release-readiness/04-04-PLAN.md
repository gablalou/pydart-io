<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI publish job → real PyPI | The workflow authenticates as the publishing principal to upload artifacts to the public index |
| chosen distribution name → PyPI global namespace | A confusable/typosquatted or already-taken name is a spoofing/dependency-confusion vector |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Spoofing / Elevation of Privilege | PyPI publish authentication | high | mitigate | OIDC trusted publishing (short-lived, workflow-run-scoped credential); no long-lived `PYPI_API_TOKEN` stored anywhere (Task 1 + Task 2) |
| T-04-SC | Spoofing (dependency confusion) | chosen PyPI name `pydart-io` | high | mitigate | Task 2 re-verifies `pydart-io` is still unclaimed immediately before publish (registry state is only ~7-day-valid); refuse to publish under a confusable name if taken |
| T-04-02 | Elevation of Privilege | workflow `permissions:` | medium | mitigate | `id-token: write` scoped to the publish job only; all other jobs default read-only (Task 1 acceptance criterion) |
</threat_model>
