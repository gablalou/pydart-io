<objective>
## Phase Goal (MVP user story — derived from ROADMAP Phase 3 Goal, which is stated as "A user can read and write Parquet files...")

**As a** Python/data user of Flint, **I want to** write a flint.Table to a Parquet file and read it back into a flint.Table, **so that** I can persist and reload Arrow-format columnar data directly against Flint's core without routing through pyarrow.

Deliver the thinnest complete end-to-end Parquet round-trip: `Table.to_parquet(path)` writes a
(snappy-default) Parquet file and `Table.from_parquet(path)` reads it back into an equal `Table`
(PARQ-01, basic PARQ-02). Compression-codec choice and row-group sizing are refined in Plan 02;
predicate pushdown/projection in Plan 03; dtype fidelity + WR-01 + multi-file in Plan 04.

Before any dependent Parquet work is built, this plan lands the **mandatory Wave-0 fidelity gate**
(RESEARCH Assumption A6): a pure arrow-rs round-trip test proving `DataType::Dictionary`
(with `dict_is_ordered`) and an exact non-UTC tz string survive a write-then-read via the default
`ARROW:schema` embedded-metadata mechanism — the assumption PARQ-06 (Plan 04) depends on.

Purpose: prove the core Parquet write/read pipeline works end-to-end and de-risk the schema-fidelity
assumption before Plans 02-04 build on it.
Output: `flint-core/src/parquet_io.rs` (write_parquet/read_parquet), `from_parquet`/`to_parquet`
`#[pymethods]`, the Rust Wave-0 fidelity probe, and a Python round-trip test.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller path arg -> from_parquet/to_parquet | Untrusted str/Path values cross into filesystem open/create calls. |
| Parquet file bytes -> read_parquet | A file at a caller-supplied path is untrusted input (may be corrupt/malformed/attacker-controlled). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Denial of Service / Tampering | read_parquet metadata/footer parse | high | mitigate | Use the parquet crate's Result-returning API (try_new/build) and `?`-propagate every parse error into FlintError; NEVER .unwrap()/.expect() on a parse Result from file bytes not written by this process. A corrupt footer surfaces as a caught FlintError, not an interpreter-aborting panic (ASVS V5). |

Documented as caller responsibility, not a Flint-owned mitigation. |
